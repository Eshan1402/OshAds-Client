Where we stand

The foundation is good. Three gaps block traffic.

Already working

  • Explainable recommender with sponsored labels and diversity re-rank (src/lib/recommend.ts)
  • Campaign console with roles, analytics, reports
  • Claude connector with 12 growth tools, a plugin and a social agent behind a human approval queue
  • Code-split, accessible front end that passes typecheck

Gap 1: invisible to search

  • Pages render only in the browser, so Google and link previews see one generic page
  • No sitemap, robots.txt, Open Graph or structured data

Gaps 2 and 3: no real data

  • Everything runs on sample data and localStorage; there is no backend yet
  • No event tracking, so we cannot tell clients which visit led to an install, or tune the recommender
Acquire visitor→ Land on an app page→ Recommend→ Install click→ Measure→ Learn & re-rank↺

Every item in this plan feeds one step of this loop. The loop only compounds once the Measure step exists, which is why tracking comes first.

Ground rule

Real people only

No bots, click farms, incentivised fake installs or traffic exchanges. App stores and ad networks detect them, refuse the installs and can ban our clients' accounts. Our product is installs that stick, and clients will judge us on retention. Sponsored placements stay labelled, as the recommender already does.

// Thompson sampling for a featured slot (sketch for src/lib/bandit.ts)
function pick(arms: { id: string; clicks: number; views: number }[]) {
  let best = arms[0], bestDraw = -1
  for (const a of arms) {
    const draw = sampleBeta(a.clicks + 1, a.views - a.clicks + 1)
    if (draw > bestDraw) { bestDraw = draw; best = a }
  }
  return best.id
}

Roadmap

90 days, in three phases

Days 0–30Foundations
  • Backend (Node + Postgres) behind services/api.ts; move login server-side and remove passwords from the bundle
  • Event tracking endpoint and consent banner (GDPR/CCPA) before any pixel loads
  • Pre-rendering, per-page meta, JSON-LD, sitemap, robots.txt; submit to Search Console
  • Connect GA4, Search Console and Tag Manager through Adspirer; Windsor.ai for reporting
  • Unit tests for recommend.ts; drop gsap in favour of framer-motion to slim the main bundle

Done when: all public pages are indexed with their own titles, and an install click can be traced back to its source.

Days 31–60Channels
  • First 200 programmatic pages, each with an editor-approved intro
  • Social agent on live data for 3 pilot clients; best-time scheduling
  • First paid campaigns to app pages, with retargeting, for pilot clients
  • Wishlist, Follow category and the weekly "Picked for you" email
  • Attribution view on the dashboard

Done when: each pilot client gets a weekly report showing installs by channel.

Days 61–90Optimise
  • Thompson-sampling bandit on hero and featured slots
  • Refit recommender weights from real outcomes; add "people also installed"
  • Referral links with rewards; Featured-on-OshAds badge
  • New connector tools: seo_audit, content_opportunities, experiment_results

Done when: recommendation click-through and organic sessions both beat the Day-30 baseline.

Risks

What could go wrong, and the guardrail

  • Thin programmatic pages get penalised. Minimum 5 apps and a unique, approved intro per page; noindex anything below the bar.
  • Privacy and consent. Consent before pixels or retargeting; no personal data in URLs; data processing agreements with each connector vendor.
  • Undisclosed ads. Keep the Sponsored chip on every paid placement and disclose creator partnerships (FTC and ASA rules).
  • Runaway ad spend. Paused-by-default campaigns, budget caps and human approval, as the Adspirer guardrails already enforce.
  • AI mistakes in public. Every AI-written post, reply and page goes through the approval queue; nothing auto-publishes.
  • Demo-only security. Client-side login must be replaced before any real client data goes in.
